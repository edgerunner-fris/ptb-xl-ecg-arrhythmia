# 面试问答题（15 个）

每题的回答都对应本项目的一次真实运行；数字可在 `results/*.json` 或
[`RESULTS_TABLE.md`](RESULTS_TABLE.md) 中核对。

---

### 1. 为什么做双头（5 超类 + 12 节律），而不是一个 17 类多标签头？

两套标签的语义层级不同：超类是诊断结论（CD/HYP/MI/NORM/STTC），节律是心律状态（SR/AFIB/…）。
合成一个头会让损失被样本量大的类主导，而且一个头的阈值无法同时适配两类分布。分开后
每头有独立的 masked BCE、独立选模和独立标定。代价是参数量略增，但编码器共享，
总参数只增加两个线性层。实测两头难度差异很大：ResNet 上超类 0.9239、节律 0.9320，
而 Transformer 上超类 0.9133、节律只有 0.8662——如果合并，这种差异会被平均掉。

### 2. 为什么必须按患者切分？你怎么验证没有泄漏？

同一患者常有多条记录（本库人均 1.155 条，最多 10 条），且同一人的心电图高度相似。
按记录随机切分会让同一患者的记录同时出现在 train/test，指标虚高。这里直接用官方
`strat_fold`：train 1–8、val 9、test 10，切分文件固化在 `splits/main_v1.json`。
验证方式是把三个集合的 `patient_id` 取交集，结果 `train∩val = train∩test = val∩test = 0`，
并且没有任何患者跨 fold（记录在 `results/m0_data_report.json`）。

### 3. 为什么用 statement-masked 评测？不 mask 会怎样？

PTB-XL 里一条记录只标注它实际写了的 statement。比如没有节律 statement 的记录，
不能认定它"没有 AFIB"。如果按全量当负样本，稀有类会被大量伪负例稀释，AUC 虚高。
所以每个头只在该类有 statement 的记录上算 loss 和指标：超类 2,158 条、节律 2,098 条
（test 共 2,198 条）。副作用是两头的评测集不同，跨头比较要看各自口径。
另外 macro-AUC 里包含只有 2–8 个正例的类，噪声很大，所以同时报
`stable_min10` / `stable_min20`（只保留正例 ≥10/≥20 的类）。

### 4. 为什么 patch Transformer 输给 ResNet？加宽为什么没补上？

test masked：ResNet 0.9239/0.9320，Transformer 0.9133/0.8662，差 0.0106/0.0658。
加宽到 2.16M 参数后是 0.9130/0.8824——超类几乎不动，节律补回 0.0162 但仍差 0.0496。
解释：12 导联 ECG 的判别信息高度局部（QRS 形态、ST 段），卷积的局部连接和平移等变性
是强先验；Transformer 要从 82 个 token 里自己学出这些结构，17k 条训练记录不够。
加宽只增加容量，不改变归纳偏置，所以超类没收益；节律头原本容量不足，加宽才有部分收益。

### 5. MSM 为什么在原始采样点做掩码，而不是 token 级？

patch 25 / stride 12，相邻 token 重叠 13 个采样点。如果在 token 级掩码，一个被遮的 token
里超过一半的采样点仍能从邻居 token 看到，重构任务变成"抄邻居"，学不到东西。
所以掩码在 tokenizer 之前做：8 段 × 50 个采样点，覆盖名义 40%（实际 0.3349），
并且 loss 只算被掩码的采样点。这个 bug 是在检查 mask 覆盖率与重构误差时发现的，
修复前的结果全部作废重跑。

### 6. 对比学习在你的实验里到底有没有用？

分情况。**冻结编码器时有用**：linear probe 100% 标签，joint（MSM+对比）0.8780/0.8663，
MSM-only 0.8657/0.8385。**全量微调时没用甚至略负**：100% 时 joint−MSM 超类 −0.0019/−0.0037、
节律 −0.0169/−0.0081（seed 42/43 同号）。解释：全量微调时任务损失会自己重塑表示，
对比目标只是在 30 个 epoch 的预训练里占了一部分容量；而在冻结特征时，表示质量直接决定线性头，
对比学习提供的类间可分性才有价值。结论：不要默认"多目标=更好"，要看适配方式。

### 7. 你怎么确认 1% 标签下的提升不是噪声？

第一次只跑了 seed 42，超类 1% 的 joint−scratch 是 +0.0347，看起来很好。但 1% 只有 165 条记录，
这个量级完全可能是 seed 噪声，于是用 seed 43 重跑同一比例（同一患者子集，只换初始化与采样）。
结果超类变成 −0.0039，**没有复现**，所以撤回了"低标签下超类也有 SSL 增益"的说法。
节律头 seed 43 是 +0.1081（seed 42 +0.0873），方向一致、幅度更大，这个结论保留。
100% 时超类 −0.0002/+0.0044，本来就不该宣称有提升。

### 8. 标签比例子集为什么要嵌套？你的子集是嵌套的吗？

我的不是嵌套的：每个比例用独立随机种子在患者层面抽样。这意味着 5% 的子集不包含在 10% 里，
曲线不保证单调。实测节律头 5% 是 0.7807、10% 是 0.7640，回落 0.0167——这是抽样差异，
不是"数据变多反而变差"。如果要做严格的样本效率曲线，应该用嵌套子集（10% 包含 5%），
但那样各点之间又不独立。我在报告里明确写了这一点，避免把抽样噪声讲成训练效应。

### 9. 温度缩放为什么不会改变 AUC？T<1 说明什么？

温度缩放是单调变换 p → sigmoid(logit / T)，只改变概率刻度，不改变任意两条样本的排序，
所以 AUC 不变——实测最大 |ΔAUC| 1.1e-16（浮点噪声），这是一个很好的自检。T < 1 表示模型**欠自信**：
logit 被压得太扁，实际正确率高于预测概率。这里节律头 T = 0.8426，超类 T = 1.1113（过自信，轻微）。
效果有限：ECE pooled 超类 0.0164→0.0140、节律 0.0074→0.0043，因为模型本来就很校准。
逐类并非都改善，HYP 的 ECE 反而从 0.0416 升到 0.0495——单一温度不可能对每个类都最优。

### 10. 多标签 conformal 的边际覆盖为什么会"骗人"？

逐类做 conformal，每类覆盖 90%，但"每条记录所有类都覆盖"的联合覆盖会低得多：
超类 0.6645、节律 0.5620（α=0.1）。更严重的是节律头：边际覆盖 0.8913 看似达标，
但平均每条记录有 1.1735 个空集、41.3% 的记录至少一个空集，正类召回只有 0.1808。
也就是说达标是靠把稀有类判成空集（自动预测为负）换来的。
诊断方法就是同时看正类召回、空集率、集合大小，而不是只看一个覆盖率数字。

### 11. Mondrian conformal 为什么在节律头退化？

Mondrian 对正负样本分别取分位数。节律头里 AFLT/BIGU/PSVT/SVTAC/TRIGU 的校准集正例
分别只有 7/8/3/3/2 个。α=0.1 时非退化所需的最小正例数是 ceil((1−α)/α) = 9，
不够时 `ceil((n+1)(1−α)) > n`，分位数只能取 1.0，正类阈值变成 0（所有记录都包含正标签），
同时负阈值很小，于是 88%–90% 的记录同时包含正负标签。结果是正类召回 0.9280 很好看，
但正集合数 7.2707/12、both 集合 5.6511 条/记录，完全不能当决策规则。
超类头没有这个问题：正类召回 0.7430→0.8938，正集合数 1.9458，可用。

### 12. 为什么 PACE 的覆盖低于名义值？这是算法问题还是数据问题？

PACE 边际覆盖 0.8937（名义 0.9），Mondrian 正类召回 0.6786，是节律头非退化类里最差的。
原因是分布偏移：校准集正例平均置信度 0.9233，test 0.7578，差 0.1655。
模型在 val 上早停，又在同一 val 上估计分位数，val 的分数与 test 不满足交换性，
所以 conformal 的有限样本保证不成立，覆盖只能当经验值看。
修法是留出独立的校准集，或用 cross-conformal；本项目没有额外数据，所以如实报告而不是掩盖。

### 13. attention rollout 能解释这个模型吗？

只能给弱定位。5 个样本上 top-10% 注意力质量均值 0.1952，均匀基线是 0.10——
有集中，但远不如同批样本的 gradient×input（0.5423）。更关键的是两个结构性限制：
rollout 解释的是 CLS 表示，**class-agnostic**，不能说明"为什么是 MI"；注意力在时间 token 上，
没有导联轴，回答不了"哪个导联"。所以图只能作为定性展示，不能当诊断依据。
要做类特定解释，应该对某个 logit 做梯度，或做类条件注意力。

### 14. 蒸馏为什么比自监督更有效？

test masked 下，同架构学生的节律 AUC：从头训练 0.8662，自监督预训练（100%）0.8836，
蒸馏 **0.9160**。蒸馏用 844,945 参数（教师的 21.9%）把节律差距从 0.0658 缩到 0.0160。
原因：教师软标签直接编码了类间相似性和样本难度，相当于给了一个密集的监督信号；
而 MSM 只要求重构信号，对比学习只要求同记录不同视图接近，两者都不直接告诉模型"这个样本
离 MI 和 STTC 的边界有多远"。超类头蒸馏只 +0.0019，因为教师本身在超类上就没比学生强多少。

### 15. 动态 int8 量化为什么 batch 1 反而更慢？

实测 batch 1：13.07 → 18.21 ms（x0.72）；batch 32：349.02 → 328.57 ms（x1.06）。
动态量化只量化 `nn.Linear`（这里 10 个），每次 forward 都要在运行时对激活做量化/反量化，
小 batch 下这部分固定开销盖过了矩阵乘的收益；batch 32 摊薄后才略有正收益。
体积收益是实的：3.40 → 1.83 MB（1.86×），精度几乎不变（节律 0.9161→0.9157）。
如果目标是延迟，应做静态量化（需要校准数据）或直接用更小的模型，而不是动态量化。
另外实现上有个坑：量化后的 `Linear.weight` 是绑定方法，fast path 守卫会报
`AttributeError`，必须对 fp32 和 int8 都关闭 `torch.backends.mha.set_fastpath_enabled`。
